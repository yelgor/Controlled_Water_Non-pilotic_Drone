# Як влаштована прошивка

Розбір ідеї кожної частини коду: що робить, навіщо і як модулі пов'язані між собою.

## 1. Що робить катер

Це **аероглісер**: пропелер дме повітрям назад, кермо стоїть у цьому потоці.
Прошивка на ESP32-S3 50 разів на секунду:

1. **читає** пульт, компас і GPS;
2. **вирішує**, у якому режимі вона зараз і що робити;
3. **керує** серво керма й мотором;
4. **записує** все в лог.

Пілот керує сам (MANUAL); тумблер HOLD — човен **сам тримає курс** (PID), за бажанням ще й швидкість.

## 2. Головне архітектурне рішення: `lib/` проти `src/`

```
firmware/
  lib/   ← «мозок»: чиста логіка й математика, НЕ знає про залізо
  src/   ← «руки й очі»: драйвери заліза, flash, консоль
  test/  ← тести для lib/, запускаються на ноутбуці
```

Усе, що можна перевірити без човна (PID, режими, безпека, математика компаса), живе в `lib/`
і приймає звичайні числа. Тому `pio test -e native` за кілька секунд проганяє всі перевірки
на ноутбуці — без плати і без води. `src/` — тонкий шар: перетворює залізо на числа і назад.

## 3. Один цикл (`src/main.cpp`)

```
loop() крутиться постійно:
  rcLink.poll()   ← забрати байти з приймача ELRS
  gps.poll()      ← забрати байти з GPS
  console.poll()  ← чи не ввели команду з ноутбука

  кожні 20 мс (50 Гц):
    imu.read()                    → компас + акселерометр
    in = {пульт, курс, GPS-швидкість, чи все OK}
    st = vehicle.update(in)       → МОЗОК: режим + PID → імпульси
    actuators.write(st.pulses)    → серво і ESC
    handleLogging()               → рядок у чергу логу

  feedWatchdog()   ← «я живий»; цикл завис на 2 с → перезавантаження
```

`main.cpp` нічого не вирішує сам — лише з'єднує модулі.

## 4. Модулі

### Пульт — `lib/rc/crsf_parser`, `src/drivers/rc_crsf`

- Приймач ELRS шле по UART (420000 бод) кадри **CRSF**: `[адреса][довжина][тип][дані][CRC]`.
- Парсер збирає байти в кадр, **перевіряє CRC** (биті кадри відкидаються), розпаковує
  **16 каналів по 11 біт**.
- Сирі 172…1811 → кермо −1…+1, газ 0…1, тумблер ON/OFF (ON — тільки верхнє положення).
- **Втрата зв'язку:** понад 0.5 с без кадрів → `linkOk = false`.

### Компас — `src/drivers/imu`, `lib/nav/`

- **Автовизначення чипа:** спершу LSM9DS1, якщо немає — FXOS8700 (звідси помилки I2C при старті).
- **Осі перераховуються** під човен: x — ніс, y — правий борт, z — вниз (`config.h`, `kMagMap`).
- **Компенсація нахилу** (`heading_math.h`): човен хитається, тому
  1. акселерометр показує, де «низ» → крен і тангаж;
  2. вектор магнітного поля проєктується на горизонталь;
  3. `atan2` → курс 0–360°.
- **Фільтр акселерометра** (α = 0.1, ~0.2 с) — вібрація мотора не трясе курс.
- **Калібрування** (`mag_calibration.h`, `cal start` / `cal stop`): крутиш човен по колу,
  запам'ятовуються min/max по осях →
  **зміщення** = (max + min) / 2 (постійне поле від заліза, hard iron),
  **масштаб** вирівнює сплюснуте коло (soft iron).

### GPS — `src/drivers/gps_neo6m`

- При старті налаштовується командами UBX: **5 вимірів/с**, зайві NMEA вимкнені (щоб вистачило 9600 бод).
- TinyGPSPlus розбирає NMEA: **швидкість** (за ефектом Доплера), **супутники**, **координати**.
- `GPS OK` — є фікс, ≥ 5 супутників, дані свіжіші за 1.5 с.
- У спокої NEO-6M «тремтить» на 0.3–1 м/с — нижче ~1 м/с це фактично шум.

### Мозок — `lib/core/vehicle`

| Режим | Коли | Кермо | Газ |
|---|---|---|---|
| **FAILSAFE** | пульта немає > 0.5 с | центр | 0 |
| **DISARMED** | не армований | стік (перевірка серво) | 0 |
| **MANUAL** | армований | стік | стік × `thr.max` |
| **HOLD** | армований + HOLD + компас OK | **PID курсу** | стік або **PID швидкості** |

Безпека:

- ARM лише при газі < 5% і лише на **перемиканні** тумблера OFF→ON
  (увімкнули плату з тумблером ON або пропав зв'язок → перещелкнути).
- Без компаса HOLD неможливий → MANUAL. Без GPS швидкість не тримається → газ зі стіка.
- NaN / Inf на вході → безпечне значення.

Переходи:

- Увімкнули HOLD → **поточний курс стає заданим**.
- **Bumpless transfer:** PID «підхоплює» кермо з того положення, де воно було — без ривка.

### PID — `lib/control/pid`

Задане значення (курс 90°) мінус виміряне (80°) = помилка 10°. PID рахує кермо:

- **P** — більша помилка → більше кермо (основа);
- **I** — помилка довго не зникає (бічний вітер, кривий трим) → поступово додає;
- **D** — курс швидко наближається до заданого → гальмує, щоб не проскочити.

| Фішка | Навіщо |
|---|---|
| реальний dt з `millis()` | цикл «гуляє» — розрахунок не ламається |
| D від виміру, а не помилки | зміна заданого курсу не смикає кермо |
| НЧ-фільтр D | шум компаса не трясе кермо |
| anti-windup | інтеграл не «накручується», коли кермо в упорі |
| slew rate | кермо змінюється не швидше за `hdg.slew` од/с |
| wrap 360° | 350° → 10° — це 20°, а не 340° |
| без динамічної пам'яті | жодних `new` / `malloc` |

### Регулятор курсу — `heading_controller`

PID для курсу, вихід −1…+1. Особливість аероглісера: газ < `hdg.minthr` → потоку на кермо немає →
**інтеграл заморожується** (інакше на місці накрутився б до упору).

### Регулятор швидкості — `speed_controller`

PID для газу, вихід 0…1 (мотор не реверсивний). Плюс **feedforward** `spd.ff`: одразу дає
приблизно потрібний газ, PID лише доводить. GPS пропав → газ 0.

### Мікшер — `lib/control/mixer.h`

- кермо −1…+1 → **1100…1900 мкс** (трим, реверс серво);
- газ 0…1 → **1000…2000 мкс** для ESC, обмежено `thr.max`; увесь хід стіка розтягнутий на 0…`thr.max`;
- `rudderSpeedScale`: чим швидше, тим менший хід керма — лінійно від 100% на місці
  до `rud.min` на швидкості `rud.vmax` (без GPS замість швидкості — газ).

## 5. Інфраструктура

| Модуль | Що робить |
|---|---|
| `params.h` + `param_table` | усі налаштування в одній структурі; назва, межі, опис → `get` / `set`; неправильне значення не приймається |
| `param_store` | збереження в flash (NVS) командою `save`; **номер версії** — змінилась структура → старі дані ігноруються |
| `flight_log` | лог у flash (LittleFS, ~13 МБ); **окрема задача на ядрі 0** з чергою — керування на ядрі 1 ніколи не чекає flash; новий файл на кожен ARM |
| `telemetry_csv` | формат рядка: однаковий для файлу і `tele on`; включає `lat`, `lon` |
| `serial_console` | `status`, `get`, `set`, `save`, `cal`, `log`, `servo`, `i2c`, `tele` |
| watchdog | цикл завис на 2 с → перезавантаження (краще, ніж застигнути з мотором) |
| `actuators` | найперше після ввімкнення: газ 0, кермо в центр — ESC не стартує |

## 6. Інструменти (`tools/`)

- `get_log.py` — злити лог з плати;
- `plot_log.py` — графіки курсу, керма, швидкості, газу;
- `map_log.py` — карта маршруту на супутниковому знімку, колір = швидкість.

## 7. Тести (`firmware/test/`)

По папці на модуль: `test_pid`, `test_heading`, `test_speed`, `test_mixer`, `test_vehicle`
(режими й безпека), `test_sensors` (компас, калібрування, CRSF), `test_tuning` (параметри,
команди, формат логу). Правило: після змін `pio test -e native` зелений і `pio run -e esp32s3` збирається.

## 8. Тимчасовий тестовий режим

`include/config.h`: `kArmSwitchBypass = true` — тумблери ARM і HOLD ігноруються, човен армиться сам
при газі 0, **працює тільки MANUAL** (PID не задіяний). Перед тестами PID і виходом «по-справжньому» —
повернути `false`.

## 9. Чого ще немає

- автоповернення (RTH) і руху по точках — координати вже пишуться, це перший крок;
- калібрування компаса на зібраному човні;
- налаштування PID на воді (стоять обережні заводські значення).
