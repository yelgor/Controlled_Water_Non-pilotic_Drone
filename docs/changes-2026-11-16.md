## Деталі

### 1. Тестовий режим без тумблерів (ТИМЧАСОВО)

- `config.h`: `constexpr bool kArmSwitchBypass = true;`
- `Vehicle::setArmSwitchBypass(bool)`: коли увімкнено, ARM-тумблер ігнорується — човен армиться сам,
  щойно є пульт і газ < 5%. Втрата пульта → DISARM, як і раніше; після повернення зв'язку — знову газ у нуль.
- `main.cpp`: у цьому режимі `in.rc.holdSwitch = false` → завжди MANUAL (PID не задіяний).
- При старті друкується `!!! ТЕСТ: тумблери ARM і HOLD вимкнено`.
- Тести: `test_bypass_*` у `test/test_vehicle`.
- **Перед тестами PID і «справжнім» виходом на воду повернути `false`.**
- Побічний ефект: команди `servo`, `log dump`, `log clear`, `cal start` вимагають DISARMED →
  у тестовому режимі треба вимкнути пульт.

### 2. Лог у фоновій задачі (баг: перезавантаження кожні ~30 с)

**Симптом:** `task_wdt: loopTask (CPU 1)` через ~7–120 с після `лог NNN: запис`, обидва ядра в IDLE —
`loopTask` заблокований (не крутиться), а не завис у циклі. На flash накопичилось ~45–117 файлів логів.

**Причина (гіпотеза, не доведена до рядка коду):** `file.flush()` / запис у LittleFS блокує на секунди —
ймовірно обслуговування метаданих LittleFS при багатьох файлах у корені. Watchdog = 2 с.

**Рішення:** `FlightLog` тепер:
- `begin()` створює чергу (`xQueueCreate`, 50 × 256 Б ≈ 13 КБ) і задачу `flightLog` на **ядрі 0**, пріоритет 1;
- `start()` / `write()` / `stop()` — неблокуючі (`xQueueSend(..., 0)`); черга повна → рядок відкидається,
  лічильник `dropped()` видно в `log list`;
- задача відкриває файл, пише, робить `flush` раз на 2 с (було 1 с), друкує `лог NNN: запис`;
- м'ютекс `fsLock_` між задачею і консольними командами.

**Результат:** після зміни — жодного перезавантаження в 3 заїздах по ~4–5 хв; інтервали рядків логу рівні
(медіана 100 мс, макс ≤ 151 мс).

### 3. Watchdog у консольних командах логу

`log list` на 117 файлах тривав > 2 с → перезавантаження. `list` / `dump` / `clear` тепер приймають
`feed()` і викликають його на кожному файлі; м'ютекс береться шматками по 100 мс з `feed()`.
`clear()` видаляє по 64 файли за прохід, поки є що видаляти.

### 4. Газ на весь хід стіка

Було: `throttle = stick`, потім `clamp(0, thr.max)` → при `thr.max = 0.3` вже на 30% стіка був максимум,
решта ходу «мертва». Стало: `throttle = stick × thr.max` (MANUAL і HOLD без регулятора швидкості).
Армування як і раніше перевіряє **сирий** стік < 5%. Тести оновлено + `test_manual_throttle_scaled_over_full_stick`.

### 5. Хід керма від швидкості

- `ctl::rudderSpeedScale(fraction, minScale)` у `mixer.h`: лінійно `1 → minScale` при `fraction 0 → 1`.
- `fraction = gps_speed / rud.vmax`, якщо GPS OK; інакше `throttle / thr.max` (для аероглісера газ ≈ потік на кермо).
- Масштаб застосовується **тільки до виходу на серво**; PID, `lastRudder_` і bumpless працюють з немасштабованим
  значенням. `VehicleStatus::rudderScale` — у `status` як `хід NN%`.
- Нові параметри: `rud.min` = 0.4 [0.1..1, 1 = вимкнено], `rud.vmax` = 6.0 м/с [0.5..30].
- `kParamsVersion` 1 → 2 (збережені в NVS параметри скидаються на заводські).
- Тести: `test_rudder_speed_scale_linear` (mixer), `test_rudder_reduced_*`, `test_rudder_scale_off_when_min_is_one` (vehicle).
- 0.4 і 6 м/с — стартові значення без даних з човна; `rud.vmax` підібрати за реальною макс. швидкістю.

### 6. Координати в лозі

- `GpsNeo6m::hasLocation()`, `lat()`, `lon()` (double; 0, якщо фіксу немає).
- CSV: дві нові колонки в кінці — `...,sats,lat,lon`, формат `%.7f` (~1 см).
  `formatCsvRow(..., sats, lat = 0, lon = 0)` — старі виклики сумісні.
- Тест у `test_tuning`: координати в кінці рядка, кількість колонок збігається із заголовком.
- Старі логи (до цієї зміни) координат не мають.

### 7. `tools/map_log.py`

`python3 tools/map_log.py logNNN.csv` → `logNNN_map.html`: трек на супутниковому знімку (Esri) / OSM,
колір = швидкість, старт/фініш, клік — час/швидкість/газ/кермо/курс. Тільки стандартна бібліотека Python;
Leaflet 1.9.4 з unpkg (потрібен інтернет для перегляду). Береться лише `gps_ok = 1` і ненульові координати.

### 8. Документація і `.gitignore`

- `docs/architecture.md` — розбір ідеї кожного модуля.
- `.gitignore`: `logs/`, `*_map.html` (точні координати — тільки локально), `.idea/`, `.claude/`, `.DS_Store`.

## Результати заїздів (thr.max = 0.3, тестовий режим, MANUAL)

- Електроніка стабільна: пульт 100% (0 обривів), компас 100%, GPS фікс за ~25 с, 8–10 супутників,
  серво 1100–1900 мкс, ESC до 1300 мкс.
- **Катер пливе, але повільно:** заїзд 3 — ~85 м за ~150 с на повному стіку (30% газу) ≈ 0.55 м/с;
  без газу — зупиняється. Напрямок тяги правильний. Повороти на такому газі майже не виходять.
- GPS NEO-6M у спокої показує 0.3–1 м/с шуму — швидкість < ~1 м/с без координат не означає рух.

## Відомі проблеми і що далі

1. **Мало тяги:** підняти `thr.max` до 0.5–0.6 (`set thr.max 0.6`, `save`), заїзд «15 с на половині / 15 с на повному / повороти».
2. **Компас не відкалібровано** (`mag.off* = 0`, `mag.scl* = 1`) — зробити `cal start` / `cal stop` на зібраному човні.
3. **Повернути `kArmSwitchBypass = false`** перед тестами HOLD/PID.
4. Налаштування PID курсу на воді — `docs/pid-tuning.md` (зараз `hdg.kp = 0.01`, I = D = 0).
5. **Автоповернення (RTH)** — не реалізовано. План: точка дому при ARM (GPS OK, ≥ 6 супутників) →
   `lib/nav/geo.h` (відстань / пеленг, плоске наближення, `double` для координат) → режим `Rth` у `Vehicle`
   (пеленг = уставка PID курсу, радіус прибуття 5–8 м) → тумблер CH7 → авто-RTH при втраті пульта.
6. Дрібне:
   - `loop()`: `lastTickMs = now` → частота «плаває» трохи нижче 50 Гц (PID рахує реальний dt, не критично;
     `lastTickMs += period` виправить);
   - LSM9DS1 (якщо його поставити): `setupAccel` без rate → 10 Гц за замовчуванням бібліотеки;
   - 3 помилки I2C при старті — пошук LSM9DS1 перед FXOS8700, косметика;
   - у тестовому режимі новий файл логу з'являється на кожне ввімкнення пульта/перезавантаження — періодично `log clear`.
